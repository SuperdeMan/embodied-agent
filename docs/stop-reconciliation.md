# 停止观测与受信恢复 · D021

> 设计始于 2026-10-30，2026-10-31 在 `01f18b7` 完成下述验证。仅针对仿真参考本体；不是完整 P1 或真实硬件停止认证。

## 执行顺序

1. 查明未知操作及其具体 attempt，显式确认停止对账。
2. 校验本体、资源、原准入时的 profile/资产摘要；同进程必须等待 handler 和受跟踪线程真实结束。旧操作缺少声明时继续隔离。
3. 设置控制器维护围栏，拒绝普通写入、步进和场景重置；只执行该 profile 的受控保持策略。
4. MuJoCo 推进真实模拟时间，对机械臂与夹爪全部受控关节连续采样。速度须在阈值内保持完整稳定窗口；若选择维持夹持，物体两侧接触力也须持续满足阈值。非有限状态或期限超时均不出具证明。
5. 验证一次性证据、代次、时效与资源 owner，在围栏内事务写入证据和停止子状态，再释放资源。

`OUTCOME_UNKNOWN` 保留：停止只回答当前机制是否停下，不证明抓放目标成功。旧 ID 不重放；新的操作需重新满足确认、参数、资源和 Guard。停止对账不会回零、完成原目标或清除急停闩锁。

## 证据与兼容

证据带 `source=simulation`，绑定原 attempt boot、当前 observer boot、robot_id、operation_id、attempt_id、资源 epoch、场景 epoch、profile/资产摘要、单调时钟采样时间和连续速度样本。跨重启不直接比较旧 monotonic；历史事件用于证明过去已提交的停止，新对账由新控制器重新观察。

沿用 schema v1 和原五表，只追加业务事件并更新已有 stop_state。重启恢复必须检查证据与原准入元数据完整匹配；缺失或损坏继续隔离。旧版本读取新记录可能重新隔离，属于保守降级；不能据此宣称自动回滚恢复能力已完成。

## 边界

当前本体只有仿真机械臂保持与接触感知夹持控制器；真实机械臂、底盘或腿足必须实现各自停止策略和反馈契约。停止是对受控关节的观测，不能证明环境内所有物体静止或任务成功。直接遥操作统一准入、全量 ActionEnvelope、外部控制器身份和对象级感知 TTL 仍按后续计划推进。

CLI/RPC 只接受身份和明确确认，不允许上传自证成功的 stop evidence。云端 `212f912` 不随本批主线提交更新。

## 使用入口

先查询获取真实 attempt_id，再对该尝试明确确认：

```bash
uv run --group rpc embodied operation --remote 127.0.0.1:8391 --id OPERATION_ID
uv run --group rpc embodied operation --remote 127.0.0.1:8391 --id OPERATION_ID \
    --reconcile-stop --attempt ATTEMPT_ID --confirm
```

维护操作不在 SkillRegistry 的模型工具目录中，接口仍沿用本机控制服务信任边界；确认标志不是跨主机身份认证。本批没有增加浏览器维护按钮，也没有自动重试接口。

Python 组装须使用与本体匹配的 `robot_id`，并通过 `register_sim_skills` / `register_policy_sim_skills` 绑定受信停止控制器与受跟踪线程。默认通用 `reference` 身份、未声明跟踪能力的扩展技能，以及旧版本没有准入 metadata 的未知记录，不可凭假设解除隔离。同 boot 缺失工作线程身份同样拒绝。

## 参考 profile 与持久顺序

当前 `mujoco-hold-current-v1` 观察机械臂与夹爪全部 6 个关节：速度阈值 0.02 rad/s，连续稳定窗口 0.1 秒仿真时间，最多推进 2 秒仿真、2 秒墙钟；证据消费时效为 1 秒。允许最多 0.01 rad 的模拟软限位偏差，保持目标夹在模型关节范围内。对物体双侧接触力均至少 0.01 N 且已有目标为闭合方向时，夹爪保留该已接受目标维持夹持；否则保持当前位置。接触策略、原目标、初始位置与每个稳定样本的双侧接触力进入证据。这些是该参考模型的工程判据，不是任意本体的统一安全停机指标。

实际工作线程和维护工作线程分别追踪；排队请求到达控制器时已过期则不执行。普通 write/step/reset 在维护围栏内拒绝；捕获前后都校验状态有限性及 MuJoCo 警告，避免引擎数值恢复被误当成停止。停止请求意图先持久化，完整观察证据与 stop_state 同事务写入，成功后才释放资源。

持久写入失败或未完成观察时，围栏与隔离保留。只有持久化过的有效证明可以在重启时解除原 owner 的隔离；证据损坏则重新视为 STOP_UNCONFIRMED。重复对账仅取历史证据，不能对后来的新 owner 执行停止。原 UNKNOWN 结果及任务效果始终不被改成成功。
