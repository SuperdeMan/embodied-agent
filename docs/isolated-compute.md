# 纯计算进程隔离 · D026

> 2026-11-04，参考范围已验收；应用 `505b60e` 已部署。父进程保留执行与持久权威，子进程只接收数值副本。

隔离范围为图像检测、ONNX 推理与 MuJoCo 状态副本渲染。输入/输出用严格长度、dtype、shape、有限值与请求身份校验；无 pickle、任意 callable 或原始动作 RPC。应用路径启用适配器，直接 provider 类保留作对照。DINO 接线不等于已获得真实模型质量/时延验收。

协议源为 `proto/embodiedrpc/compute/v1/compute.proto`。JSON 使用 proto 原字段名，外层五个字段均必填，拒绝重复/未知字段；外层使用 4 字节网络序长度帧，消息最大 16 MiB，单数组最大 8 MiB。单实例最多一个在途请求，不排队。进程代次、单调递增请求 ID 或响应类型不符即失败，不把旧响应当成新结果；不用无限保存请求 UUID 集合。

启动预算独立于计算预算：参考配置初始化预算 30 秒，正常计算默认 2 秒；D025 的应用观察/帧等待仍为 1 秒，启动不是给旧观察续期。预算来自受信配置，必须为有限正值；更改预算需重新验证。调用许可撤销或观察等待取消会通知计算监督器；失败后终止并检查实际退出，拒绝自动重发。关闭先请求优雅退出，再升级为强制回收，旧 I/O 未结束时不能重建。

派发前已撤销的请求不会发送给子进程，也不会误杀健康 worker；请求已在途时撤销则回收当前计算代次。已关闭的客户端不能通过一次失败调用重新激活，恢复只适用于已回收的 FAILED 实例。

Windows 子进程无可见控制台，并加入 kill-on-close Job Object；Linux 使用独立进程组，直接 worker 配置父线程死亡信号。启动与 I/O 由专用持久线程持有，直接启动基础解释器并注入项目安装目录，避免 Windows venv 重定向器造成 PID/环境歧义。子进程环境只保留运行/缓存白名单项，不透传 API-key/token 环境变量；这不构成操作系统文件/网络访问沙箱。进程组终止、直接 worker 的 wait 回收和 I/O 线程退出分别验证，Linux 孤儿后代的最终回收仍由宿主 init 负责。

渲染复制 qpos/qvel/act/ctrl、mocap、仿真时间、相机参数及已计算的几何/相机位姿；父进程释放状态锁后等待。保留已计算位姿可避免 step 后重新 forward 跨越一个积分时刻。子进程在自己的 MjData 上渲染，JPEG 编码也在子进程内，不驱动父本体。旧场景响应拒绝，渲染尺寸缓存上限 8 组；任意外部修改 MjModel 不属于该快照协议。物理控制本身仍在父进程，不能把本批等同真实执行控制器的原生崩溃隔离。

恢复只创建新计算代次，不重试旧动作、修改调用/停止状态或清除资源隔离。D021 停止对账、D022 写入许可和 D023 对象年龄保持独立。新依赖、数据库迁移、硬件控制或跨机模型部署不在本批范围。

应用工厂启用隔离的检测/ONNX provider，渲染默认隔离；`isolated_render=False` 仅保留作直接参考路径。`registry.restart_compute()` / `sim.restart_renderer()` 是受信 Python 维护入口，要求本体空闲，不能在未知隔离未解除时恢复计算。停机先撤销调用、请求正在运行的计算退出，再等待实际工作排空和关闭账本；通用不可中断的父进程回调仍可能拒绝关闭。

Windows 验证覆盖父进程退出、所属后代停止、未退出 I/O 禁止替代代次、模型文件变化拒绝恢复、配置快照不可通过外部字典修改、关闭实例不可重新激活。计算进程死亡接入真实仿真后，父状态未产生新动作，操作仍 UNKNOWN；确认停止后才允许受信恢复，旧 ID 不重放。

实现中修正了两项跨边界问题：直接启动解释器并绑定真实子 PID/安装目录，避免 venv 重定向层歧义；渲染保留已计算位姿，避免在子进程重新 forward 后偏移一个积分时刻。JPEG 编码也移入渲染 worker，控制台关闭会主动请求在途计算退出。渲染 worker 不加载无关 Provider 模块，降低冷启动负担。
