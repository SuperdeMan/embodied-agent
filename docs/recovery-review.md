# 恢复审查快照与权限边界 · D029

> 2026-11-04，实施中。本批完善只读审查协议，不签发执行授权、不修改 schema。

## 当前接口

`GET /api/tasks/{task_id}?assess=1`、`ReconcileTask` RPC 及 `embodied task --remote HOST --id TASK --reconcile` 返回 `recovery_review`：

- 绑定 task、计划版本、robot、账本 boot、控制器 boot、scene/profile；逐步关联 operation、attempt、请求摘要、历史调用/停止状态与效果证据 ID。
- `state_digest` 用于比较接收端审查状态，是非认证摘要，不是签名或 bearer token，也不允许作为执行参数。
- `coherent` 表示读取与异步检查期间接收端可观察状态是否一致。日志写入、外部 SQLite 提交、技能声明/实现、活跃许可、控制上下文或 Guard 生命周期变化使整份评估失效，所有当前效果改为 UNKNOWN。Guard 记录递增代次，使一次急停后复位也可被识别。
- 较早的检查在返回前累计等待时间；RPC 再加本地测量的整个 RTT，不比较两台机器的 monotonic。异常或过期年龄拒绝，历史记录不被改写。
- `execution_authorized=false`、`authenticated_subject=null`、`automatic_resume_allowed=false` 始终保持；缺少身份适配与执行协议明确列入 blockers。

快照不写入账本、不观测停止、不重放动作，不自动重试评估。状态不一致时应重新读取并重新审查，不能拿旧摘要放行。它描述已有证据资格，不宣称原子物理世界状态，也不把 FINISHED 当作任务成功。

新客户端要求 D029 审查契约；旧服务缺字段或返回未知版本时拒绝审查结果，普通历史查询保持兼容。TaskReply JSON 增加字段，无 proto wire 或 schema 变更，无新增日志事件类型。

## 后续执行授权的必要条件

| 条件 | 接收端必须核对 | 当前状态 |
|---|---|---|
| 操作者身份 | 由受信会话/传输适配得出主体、认证来源和权限；拒绝客户端自报管理员 | 尚未实现；本批明确拒绝授权 |
| 明确动作范围 | 停止对账、效果重查、新任务或续跑分别授权，不合并成泛化的“恢复” | 现有停止/效果接口保持原边界 |
| 目标绑定 | task/plan/operation/attempt/请求摘要，以及控制器、场景、profile、证据引用 | 只读审查已提供绑定 |
| 新鲜度与一次性消费 | 有限有效期、提交时再次核对，过期/已消费/上下文变化拒绝 | 只有证据年龄与审查失效检查；未签发凭据 |
| 持久审计 | 先写授权决定及消费意图，再产生副作用；存储失败不得执行 | 执行授权审计尚未实现 |
| 未知结果 | UNKNOWN 不改成功，不按旧 operation_id 重试；停止与效果分别证明 | 既有门禁保持 |

`confirmed=true` 是确认信号，不是身份认证。本批不把现有本机参考 RPC 或私网访问升级成已验证的跨机操作者认证。身份适配、授权审计和执行接口需在具体部署方案中一起验收，然后才讨论多 attempt。

## 验收范围

覆盖评估期间的场景/profile/技能/控制代次/账本变化、真实 Guard 急停复位、等待老化、异常年龄、取消无写入、真实仿真身份绑定、RPC 伪造授权声明和传输老化。P1 矩阵继续明确保留真实设备、跨机身份和执行恢复未关闭项。
