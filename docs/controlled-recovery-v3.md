# 受控单步恢复与账本 v3

2026-11-28 已批准实现、隔离演练及通过验收后的常驻库迁移。迁移前运行格式为 v2。任务恢复审查只读，既有维护作用域分别处理停止对账和效果重查。

## 数据与动作

- 保留逻辑操作的 `operation_id` 和请求摘要。将 `attempts.operation_id` 的唯一约束改为 `UNIQUE(operation_id, attempt_no)`。已有尝试的编号统一为 1，保留原 `attempt_id`、资源、控制代次、时间和事件引用。按尝试保存结果，迟到回执只能命中对应的尝试。
- 新增 `recovery_grants` 记录一次性授权的摘要、受信操作者、任务及计划版本、操作、上一尝试、请求及审查摘要、控制代次、期限和消费关联。明文凭据不入库。每个操作最多一个运行中的尝试，每份授权最多消费一次。
- 首个执行范围为人工确认的单步重试。必须取得当前场景与配置、停止及效果证据。效果已经满足时无需重试，效果未知、停止未确认、资源隔离或 Guard 闩锁时拒绝。原尝试的 UNKNOWN 保留。受信接收端在同一事务内消费授权、建立新尝试并记下意图，提交成功后才走既有技能准入与 Guardian。重复请求、重启和过期授权均不得触发第二次动作。整份计划继续保持人工审查。

## 迁移与演练

1. 先用副本干跑。维护态取得独占锁，以在线备份固化 v2 七表摘要，检查完整性、外键及运行中的操作。无法独占或存在运行中的操作就拒绝。
2. 在一个事务内重建尝试表的约束与关联，追加授权表，核对历史七表原字段、事件归属和外键后登记版本。旧应用应拒绝打开 v3。部署新代码不能隐式迁移已有账本。
3. 故障验收覆盖迁移中断、并发或重复消费、授权过期或上下文变更、意图提交后崩溃、迟到回执、跨进程身份和审计写入失败。每项同时核对设备动作数、尝试数和历史记录。
4. v3 产生新记录后，拒绝会丢失历史的 v2 回退，并用保留新历史的 v3 恢复。仅在能证明没有迁移后的新写入时，才演练用已认证的迁移前备份恢复 v2。

常驻实例在本机及 Linux 隔离演练通过后，停写、复核现场 v2 数据、生成新的认证备份，再迁移和激活。保留原私网入口及操作者作用域。

## 运行入口

- `embodied ledger-upgrade --ledger PATH --to 3` 在副本上预演，追加 `--apply --backup-dir DIR` 后才会停写检查、备份并迁移。新建参考库继续使用 v2，升级显式执行。迁移后的八张表包含原七表与 `recovery_grants`，版本行记录 v2 来源摘要和首笔 v3 业务写入标志。与库同目录的 `.schema-v3` 标记用于主库损坏时识别曾迁移的路径，备份或搬迁应保留该标记。
- 单步重试限于已结束或中断计划中、具有确定性状态谓词的受跟踪技能。先取得原 UNKNOWN 尝试的停止实证，完成独立效果重查并得到当前 UNSAT，再以明确授予 `retry_step` 的操作者申请。消费时重新观测效果并校验原对象绑定。需要单独危险动作确认的技能保持原有重试限制。
- 受控 HTTP 复用 `/api/operator/authorizations` 与 `/api/operator/confirmations`。mTLS 使用 `PrepareStepRetry` 与 `ConfirmStepRetry`。CLI `embodied retry-step --remote HOST --task TASK --operation OP --attempt ATTEMPT` 配合操作者 TLS 参数，展示具体技能与参数，录入明确答复后提交。无鉴权回环开发服务不能为这两个 RPC 签发授权。
- 查询 `GET /api/tasks/{task_id}` 或 `GetTask` 可逐次查看结果和证据，原操作的普通重发只读取已有结果。受损 v3 用认证 v3 备份恢复。回到 v2 要求迁移前认证备份、完整 v3 库、相同历史投影以及零笔迁移后业务写入。
